The problem

Companies regularly copy tables from operational databases (PostgreSQL, MySQL) into cloud storage (Amazon S3, Google Cloud Storage) as Parquet or CSV files. The copying is easy; doing it without silently damaging data is not:

  • A money column DECIMAL(18,2) stored as a floating-point number can lose paise.
  • A timestamp with a time zone can quietly lose its time zone.
  • Empty values (NULL) can turn into empty strings.
  • A JSON column can be flattened and lose its nested data.

Most tools only check that the number of rows matches, and every one of the errors above passes that check.

How the tool works

1. ConnectorReads the table structure and 20 sample rows from the database.
2. Schema MapperDecides each column's output type. Can be rules or an AI model (LLM), helped by sample values and past migrations.
3. Dry runConverts the sample rows first. If something would be lost, the plan is fixed before any real data moves.
4. ExecutorCopies all rows into Parquet/CSV files, split into monthly folders.
5. ReconciliationReads the files back and runs checks made for this table's columns: exact totals, time zones, NULLs, JSON and more.

Glossary

TermMeaning
